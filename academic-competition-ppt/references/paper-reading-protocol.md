# Paper Reading Protocol

Use this before planning a long-form paper presentation. The goal is to reconstruct how the paper thinks, not to summarize headings.

## Four Chains

### 1. Problem Chain

Identify:

- Why the author writes this paper.
- The real-world or theoretical contradiction.
- The common intuition that may be incomplete or wrong.
- The precise research question the paper tries to answer.
- Why this question matters for the field, policy, method, or practice.

Output as: `background tension -> puzzle -> research question -> why now -> why existing answers are insufficient`.

### 2. Concept Chain

Identify:

- Core concepts and how the paper defines them.
- How each concept is measured or operationalized.
- Which concept is outcome, treatment/core explanatory variable, mediator, moderator, control, mechanism, or boundary condition.
- Which concepts are easy for the audience to misunderstand.

Output as: `concept -> definition -> measurement -> role in model -> common confusion -> slide treatment`.

### 3. Identification Chain

Identify:

- Why the paper uses this model or identification strategy.
- What naive method would be biased or incomplete.
- Which omitted bias, reverse causality, selection problem, measurement issue, or timing problem the method tries to handle.
- What assumptions the method needs.
- What the method still cannot answer.

Output as: `naive approach -> why it fails -> paper method -> identifying assumption -> remaining boundary`.

### 4. Result Chain

Identify:

- What the baseline result answers.
- What mechanism tests add beyond the main effect.
- What heterogeneity tests reveal about conditions or groups.
- What robustness/endogeneity checks defend against.
- How the conclusion returns to the original problem.

Output as: `main answer -> mechanism answer -> boundary answer -> credibility answer -> contribution`.

## Reading Passes

1. **Fast map:** title, abstract, intro, hypotheses, data/model, main tables, conclusion.
2. **Anchor pass:** collect original statements for research question, definitions, data, variables, model, main findings, contributions, policy implications.
3. **Technical pass:** extract formulas, models, identification logic, coefficient meaning, table/figure roles.
4. **Narrative pass:** convert the paper into follow-up questions that an audience would naturally ask.

## Minimum Deliverable Before Slide Design

Create a compact inventory:

`slide range -> chain segment -> audience cognition task -> source anchor/table/formula -> page type -> transition question`.
