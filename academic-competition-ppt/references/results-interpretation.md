# Results Interpretation

Use this for baseline, mechanism, heterogeneity, robustness, endogeneity, descriptive, or expected-test pages.

## Result Page Structure

Each result page should answer:

`page question -> table/figure/core value -> result translation -> theory return -> next follow-up question`.

Use a full layout: table/figure as the main paper object, right-side or bottom result translation, and a bottom takeaway. Do not leave the table as a decorative thumbnail.

## What To Explain

- Which row, column, coefficient, panel, or plotted point matters.
- Direction, magnitude, significance, or expected direction.
- What question the result answers.
- How it supports, weakens, or qualifies the hypothesis.
- Why the next test is needed.

## Table Handling

- Show full table context only if readable.
- If dense, split into context slide and close-up slide.
- Highlight the key coefficient or comparison.
- Add a plain-language translation; do not leave the audience to read the table alone.
- If the table cannot be read at 11-14 pt, split it into a context slide and a close-up slide.

## Research Plans

If the source is a research plan:

- Do not invent coefficients, significance, sample size, or completed findings.
- Use language such as `拟检验`, `预期方向`, `待估计`, `若结果显示`.
- Frame pages as "this test will answer which question" rather than "this test proves".

## Mechanism And Robustness

- Mechanism pages explain why the main result happens.
- Heterogeneity pages explain where or for whom it is stronger/weaker.
- Robustness pages answer doubts about measurement, sample, model, timing, or endogeneity.
